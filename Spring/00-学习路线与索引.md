## 三、全系列约定

### 1. 只用 XML 配置

本系列**刻意不用注解**。所有 Bean 的注册与依赖注入都写在 XML 里，这样能看清「容器到底做了什么」——注解只是把同样的信息写在 Java 代码上而已，底层机制完全一致。

```java
// ✅ 本系列写法：普通 Java 类，一个注解都没有
public class UserService {
    private UserDao userDao;
    public void setUserDao(UserDao userDao) { this.userDao = userDao; }
}

// ❌ 本系列暂不使用
@Service
public class UserService {
    @Autowired private UserDao userDao;
}
```

### 2. XML 文件头统一用这个

后面各篇出现的 XML 片段，都默认放在这个头下面（为了省篇幅不再重复）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://www.springframework.org/schema/beans
                           https://www.springframework.org/schema/beans/spring-beans.xsd">

    <!-- 各个 <bean> 写在这里 -->

</beans>
```

### 2.1 常用命名空间一览（别只记 beans）

XML 配置真正写起来会用到好几个命名空间，每个都要在 `<beans>` 头上声明 `xmlns:xxx` 和对应的 `xsi:schemaLocation`，**两者必须成对出现**，否则解析时报 `SAXParseException`。

| 前缀 | 命名空间 | 用来干什么 | 本系列在哪出现 |
|------|---------|-----------|--------------|
| `beans`（默认） | `http://www.springframework.org/schema/beans` | `<bean>` / `<property>` / `<constructor-arg>`，一切的基础 | 全篇 |
| `p` | `.../schema/p` | Set 注入的简写：`p:userDao-ref="userDao"` | [03 篇](03-Spring对IoC的实现-DI依赖注入.md#42-property-能注入的所有类型) |
| `c` | `.../schema/c` | 构造注入的简写：`c:userDao-ref="userDao"` | [03 篇](03-Spring对IoC的实现-DI依赖注入.md#65-c-命名空间构造注入的简洁写法) |
| `util` | `.../schema/util` | **可复用的集合 Bean**：`<util:list>` / `<util:map>` / `<util:properties>` / `<util:constant>` / `<util:property-path>` | [03 篇 4.3 节](03-Spring对IoC的实现-DI依赖注入.md#43-util-命名空间把集合抽成可复用的-bean) |
| `context` | `.../schema/context` | `<context:property-placeholder>` 读外部配置、组件扫描 | [03 篇 4.3 节](03-Spring对IoC的实现-DI依赖注入.md#43-util-命名空间把集合抽成可复用的-bean) |
| `tx` | `.../schema/tx` | 声明式事务 `<tx:advice>` | [08 篇](08-Spring框架特点.md#22-声明式编程把怎么做变成声明什么) |
| `aop` | `.../schema/aop` | 切面配置 `<aop:config>` / `<aop:pointcut>` | [08 篇](08-Spring框架特点.md#22-声明式编程把怎么做变成声明什么) |
| `mvc` | `.../schema/mvc` | `<mvc:annotation-driven>` 等（注解式控制器才需要） | 暂不涉及 |

**需要多个命名空间时的完整写法：**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xmlns:util="http://www.springframework.org/schema/util"
       xmlns:context="http://www.springframework.org/schema/context"
       xmlns:tx="http://www.springframework.org/schema/tx"
       xmlns:aop="http://www.springframework.org/schema/aop"
       xsi:schemaLocation="
           http://www.springframework.org/schema/beans
           https://www.springframework.org/schema/beans/spring-beans.xsd
           http://www.springframework.org/schema/util
           https://www.springframework.org/schema/util/spring-util.xsd
           http://www.springframework.org/schema/context
           https://www.springframework.org/schema/context/spring-context.xsd
           http://www.springframework.org/schema/tx
           https://www.springframework.org/schema/tx/spring-tx.xsd
           http://www.springframework.org/schema/aop
           https://www.springframework.org/schema/aop/spring-aop.xsd">

    <!-- 业务 Bean、util 集合、事务通知、切面都写在这里 -->

</beans>
```

> `p` 和 `c` 命名空间比较特殊：它们**没有 XSD 文件**，所以只需要 `xmlns:p` / `xmlns:c`，不用在 `xsi:schemaLocation` 里登记。

### 4. 启动容器的最短代码

后面所有例子，跑起来都靠这两行：

```java
ApplicationContext ctx = new ClassPathXmlApplicationContext("applicationContext.xml");
UserService userService = ctx.getBean("userService", UserService.class);
```

## 四、一句话回顾

> Spring 的 DI 没有魔法：**读 XML 得到 BeanDefinition（图纸）→ 反射造对象 → 反射填依赖 → 存进单例池**。
> 所有的复杂度都在「填依赖时怎么找到正确的那个 Bean」和「什么时候填、填完还要做什么」上。
