## 数据隔离与变更

- Maven 测试仅使用 src/test/resources/application.properties 指定的内存 H2，不使用开发库密码，不连接开发 MySQL；测试建表脚本仅用于 H2。
- 当前服务测试创建独立商品 id=4，仅修改该商品；已删除并确认不存在。既有商品未被修改。MySQL自增计数会继续递增，不回退。
- POM 仅增加 test scope 的 H2 和 Surefire 3.2.5，确保 JUnit 5 实际执行。没有更改开发数据源。
- 业务级事务回滚在H2验证通过，不声称已在MySQL验证回滚；H2 MySQL模式不能完整替代MySQL。

## 如何复现

适用 Java 8/17；本轮按项目 Java 8、Spring Boot 2.7.18、Maven 3.8.8 执行。

在 BizVision 目录运行 `mvn test`（当前工具环境使用 Maven 3.8.8 绝对路径）。

当前 MySQL 服务已启动时，运行 `python3 src/test/scripts/live_mysql_checks.py`。此脚本会创建、修改并清理自己的测试商品；不会使用既有商品做扣减实验。

## 实际边界

测试通过覆盖上述场景，不代表所有输入、负载和故障已穷尽。真实MySQL扣减后故障回滚、数据库连接故障、持续负载尚未覆盖。分页列表和总数是两条查询，并发新增/删除时不承诺同一个快照；当前未建立此业务约束。
