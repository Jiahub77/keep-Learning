# 异常处理与接口入门

## 学习状态

异常处理只介绍了基础，练习已主动跳过。接口与多态刚开始学习，以下作为复习资料，不表示已经完成实践。

## 1. throw 与 try-catch

```java
try {
    System.out.println("开始创建");
    Product cup = new Product("保温杯", 9900, -1);
    System.out.println("创建成功");
} catch (IllegalArgumentException e) {
    System.out.println("参数错误：" + e.getMessage());
}
System.out.println("处理结束");
```

按之前构造器的校验，输出：

```text
开始创建
参数错误：库存不能为负数
处理结束
```

throw 抛出异常后，跳过当前正常执行流程。匹配的 catch 可以捕获并处理，getMessage 获取异常信息。处理后不会回到抛错位置重试，商品也没有创建成功。

如果异常一直未被捕获并传播到 main 之外，会结束该主线程的执行。返回 false 与抛出异常是不同机制。

## 2. 接口定义约定

以通知服务为例，接口规定发送消息的能力：

```java
public interface Notifier {
    void send(String message);
}
```

这里的方法隐含 public abstract，没有方法体。接口也支持其他形式的方法，本课只讨论这一种。

## 3. 实现接口

以下三个公开类型应分别保存为 Notifier.java、EmailNotifier.java、SmsNotifier.java。

```java
public class EmailNotifier implements Notifier {
    @Override
    public void send(String message) {
        System.out.println("邮件通知：" + message);
    }
}
```

```java
public class SmsNotifier implements Notifier {
    @Override
    public void send(String message) {
        System.out.println("短信通知：" + message);
    }
}
```

implements 声明实现接口；Override 注解帮助编译器检查方法是否正确实现或重写。示例仅打印信息，不会真的发送邮件或短信。

## 4. 多态

在 main 中调用：

```java
Notifier notifier = new EmailNotifier();
notifier.send("商品库存不足");

notifier = new SmsNotifier();
notifier.send("商品库存不足");
```

输出：

```text
邮件通知：商品库存不足
短信通知：商品库存不足
```

变量类型是接口，实际对象决定具体执行哪个实现。后续 Spring 依赖注入会经常使用这种方式。

## 5. 待复习问题

普通的、非抽象的 SmsNotifier 声明 implements Notifier，却既没有实现 send，也没有继承可用实现，能编译吗？

答案：不能。具体类必须提供接口抽象方法的实现。若声明为抽象类，可以暂不实现，但不能直接 new 该抽象类。
