# 易错点与复习清单

## 1. 本轮练习中的易错点

| 易错写法或理解 | 正确理解 |
|---|---|
| purchase(3) 后库存为 3 | 参数是购买量，库存由原库存减 3 |
| 两个变量赋值就复制对象 | 复制的是引用；new 才创建新对象 |
| 同一个键 put 后 Map 只剩一条 | 只替换该键的值，其他键保留 |
| get 不存在的键会立即报错 | 返回 null；对 null 调用对象方法才会报空指针异常 |
| purchaseById 查不到时返回 null | 内部 get 得到 null，方法按代码返回 false |
| 商品存在就无条件返回 true | 购买和补货仍可能失败，应返回业务方法的结果 |
| boolean 方法只写成功分支返回值 | 所有正常结束路径都需返回值 |
| if (product) | Java 不做对象真假转换，写 product != null |
| boolean 方法返回 getStock() | int 与 boolean 不兼容，需返回比较表达式等布尔值 |
| 先访问 product 再检查 null | 空值判断放在前面，利用短路保护访问 |
| Product::getStock() | 方法引用不带调用括号：Product::getStock |
| filter(Product::getStock > 0) | 用 Lambda：filter(p -> p.getStock() > 0) |
| 筛选后直接 sum 统计种类 | count 统计数量；数值流 sum 求和 |
| int 接收 count | count 返回 long，必要时用 Math.toIntExact |
| reversed 后仍是升序 | reversed 将比较规则反转为降序 |
| 价格低于 10000 写 > | 低于用 <，高于用 > |
| price、getPrice 随意命名 | 必须与已定义的 priceInCents、getPriceInCents 一致 |
| return false 缺分号 | Java 普通语句需以分号结束 |
| 接口变量能调用实现类特有方法 | 编译时按声明类型检查；接口变量只能调用接口声明的方法 |
| `List<EmailNotifier>` 可赋给 `List<Notifier>` | Java 泛型默认不协变；需要同时添加不同实现时使用 `List<Notifier>` |
| `List<? extends Notifier>` 可以添加任意通知实现 | `extends` 通配符适合安全读取，不能直接添加具体实现对象 |
| `default isEnabled()` 返回 false 会自动阻止 send | 必须由业务代码主动判断 `isEnabled()` |
| `Box<String>` 可以放整数 | 泛型使用时已经确定类型；整数应使用 `Box<Integer>` |
| 泛型参数可以写基本类型 | 泛型参数使用包装类型，如 `Integer`，不能写 `int` |
| record 用 `getName()` 访问 | record 访问器是 `name()`；字段不能重新赋值 |
| record 的 `==` 比较内容 | `equals()` 比较字段内容，`==` 比较是否为同一个对象 |
| `Optional.empty().get()` 返回 null | 会抛出 `NoSuchElementException`；优先使用 `orElse` 或 `ifPresent` |
| `switch` 可以直接处理 null 枚举 | `switch(null)` 会抛异常，先判断 null |

4. 如何只检查库存，而不扣库存？
5. 为什么 product != null 必须放在 getStock 调用之前？
6. 为什么 count 返回 long，而 mapToInt 后的 sum 返回 int？
7. filter 和 map 各做什么？
