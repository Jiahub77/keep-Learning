# Docker 基础

## 1. 核心概念

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| 镜像 Image | 包含程序和运行依赖的模板 | `redis:7-alpine` |
| 容器 Container | 根据镜像创建的运行实例 | 一个 Redis 进程及其隔离环境 |
| 仓库 Registry | 保存和分发镜像的服务 | Docker Hub、阿里云镜像仓库 |
| 标签 Tag | 镜像版本标记，可以被重新发布覆盖 | `mysql:8.0` 中的 `8.0` |
| Digest | 镜像内容的摘要，用于精确指定版本 | `镜像名@sha256:...` |
| Dockerfile | 构建自定义镜像的说明文件 | 安装 PHP 扩展、复制代码 |
| Compose | 用 YAML 声明和管理多个服务 | PHP + MySQL + Redis |
| 数据卷 Volume | 由 Docker 管理的持久化存储 | MySQL 数据目录 |
| 绑定挂载 Bind Mount | 将宿主机路径映射到容器 | 本机源码映射到 `/app` |
| 网络 Network | 容器之间通信的虚拟网络 | PHP 通过 `redis:6379` 访问 Redis |

镜像不会因为容器内文件变化而自动更新。删除并重建容器会丢失容器可写层中的修改，所以数据库等需要持久化的数据必须挂载保存。

Docker 容器共享内核，不是完整虚拟机。macOS 的 Linux 容器实际运行在 Docker Desktop 管理的 Linux 虚拟机中。

## 2. 镜像与容器的关系

```text
镜像仓库 --pull--> 本地镜像 --run / compose up--> 容器
Dockerfile --build--> 本地镜像 --push--> 镜像仓库
```

一个镜像可以创建多个容器，每个容器的配置和可写层相互独立。

```bash
# 单容器方式：启动一个本地 Redis，数据保存在命名卷
docker run -d --name learning-redis \
  -p 127.0.0.1:6380:6379 \
  -v learning_redis_data:/data \
  redis:7-alpine redis-server --appendonly yes
```

参数说明：`-d` 后台运行，`--name` 指定容器名，`-p` 映射端口，`-v` 挂载数据。镜像名后面的内容是容器要执行的命令或传给入口程序的参数。此例没有设置 Redis 密码，仅用于本地学习。

容器依赖主进程保持运行；主进程退出，容器也会退出。`docker run` 每次创建新容器；已有停止容器用 `docker start` 再次启动。

## 3. 端口与地址

```text
127.0.0.1:6380:6379
    │       │    └── 容器端口
    │       └─────── 宿主机端口
    └─────────────── 宿主机监听地址
```

- 宿主机工具连接 `127.0.0.1:6380`。
- 同一 Compose 网络中的其他容器连接 `redis:6379`，这里 `redis` 是服务名。
- 容器内的 `127.0.0.1` 指容器自身，不能用来访问另一个容器。
- Docker Desktop 中，容器访问宿主机服务可使用 `host.docker.internal`；Linux 需要另外配置或使用实际可达地址。
- `6380:6379` 未指定监听地址时通常发布到所有宿主机网卡；只供本机使用时优先写 `127.0.0.1:6380:6379`。
- Dockerfile 的 `EXPOSE` 只是声明端口，不会自动发布到宿主机。

## 4. 目录和持久化

```yaml
volumes:
  - mysql_data:/var/lib/mysql  # 命名卷：Docker 管理数据
  - ./src:/app                # 绑定挂载：源码来自宿主机
  - ./redis.conf:/etc/redis/redis.conf:ro # 只读配置文件
```

命名卷会在使用时自动创建，不必手动建立 `mysql/`、`redis/` 目录。绑定挂载则需要准备真实文件和目录；配置文件缺失可能导致挂载失败或被错误创建成目录。

挂载会遮住容器目标路径原有的内容，不是把两边文件自动合并。容器里的配置应填写容器路径，例如 `/app`，而不是宿主机的 `/Users/mac/...`。

## 5. Compose 最小示例

下面是独立练习项目，避免直接覆盖已有服务配置。在一个新的目录中新建 `compose.yaml`：

```yaml
services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:?请设置 root 密码}
      MYSQL_DATABASE: app
      MYSQL_USER: app
      MYSQL_PASSWORD: ${MYSQL_APP_PASSWORD:?请设置应用密码}
    ports:
      - "127.0.0.1:33062:3306"
    volumes:
      - mysql_data:/var/lib/mysql
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    command: redis-server --appendonly yes
    ports:
      - "127.0.0.1:6380:6379"
    volumes:
      - redis_data:/data
    restart: unless-stopped

volumes:
  mysql_data:
  redis_data:
```

在同目录新建 `.env`，替换示例密码：

```dotenv
MYSQL_ROOT_PASSWORD=replace-with-your-root-password
MYSQL_APP_PASSWORD=replace-with-your-app-password
```

然后运行：

```bash
docker compose config --quiet
docker compose pull
docker compose up -d
docker compose ps -a
docker compose logs --tail=100 mysql redis
```

Compose 默认创建网络，同项目的服务可使用服务名通信。无需手动给每个容器设置固定 IP。上例若与前面的 `docker run` 示例同时运行，会争用 6380 端口，应选择其中一种或修改端口。

当前 Compose 支持 `compose.yaml` 和 `docker-compose.yaml`；新配置不必写顶层 `version`。不要在同一目录放置多个默认候选文件而不确认实际加载的是哪一个。

### 常用字段

| 字段 | 作用 |
| --- | --- |
| `image` | 指定现成镜像 |
| `build` | 根据构建上下文和 Dockerfile 构建镜像 |
| `ports` | 宿主机与容器端口映射 |
| `volumes` | 数据和配置挂载 |
| `environment` | 设置容器中的环境变量 |
| `env_file` | 从文件读取容器环境变量 |
| `command` | 覆盖镜像默认命令或参数 |
| `restart` | 容器退出后的重启策略 |
| `networks` | 容器加入的网络 |
| `healthcheck` | 判断服务是否健康的检查命令 |
| `depends_on` | 定义依赖及启动顺序 |
| `platform` | 指定目标系统和架构，如 `linux/amd64` |

Compose 的 `.env` 默认用于 YAML 变量替换，不会自动把所有变量传入容器；需要通过 `environment` 或 `env_file` 传入。业务项目自己的 `.env` 又是另一份配置。

`depends_on` 的普通写法只保证启动顺序；等待数据库就绪需要 healthcheck 配合 `condition: service_healthy`，或者由应用实现重试。MySQL 的初始化账号密码通常只对首次创建的空数据目录生效。

## 6. 什么时候需要自己写 Dockerfile

直接运行官方 MySQL、Redis 时通常不需要。需要安装额外扩展、系统依赖或打包自己的程序时，再构建自定义镜像。

例如在 PHP FPM 中安装 MySQL PDO 扩展：

```dockerfile
FROM php:8.2-fpm
RUN docker-php-ext-install pdo_mysql
WORKDIR /var/www/html
```

```bash
docker build -t learning-php:8.2 .
```

此示例只安装 `pdo_mysql`，不包含 Composer、Redis 扩展或业务代码。修改 Dockerfile 后需要重新 build 并重建容器。临时进入容器安装的软件，重建后不会自动保留。

Laravel 的队列通常通过 `php artisan queue:work` 消费任务，Redis 负责保存任务；长期运行时用匹配 PHP 版本的 worker 服务或 Supervisor 管理。队列并不意味着必须额外安装 RabbitMQ。

## 7. 更新与数据保留

- 更新远端镜像：`docker compose pull 服务名`，然后 `docker compose up -d --no-deps 服务名`。
- 更新本地构建镜像：`docker compose up -d --build 服务名`。
- 修改 Compose 或 `.env`：用 `up -d` 应用；`restart` 不会更新容器环境变量和挂载。
- 修改挂载的服务配置：按服务要求 reload 或 restart；先确认文件确实被读取。
- `stop` 保留容器；`down` 移除容器和项目网络；`down -v` 还会删除命名卷。
- 镜像应选择业务支持的版本并验证架构兼容性；Apple Silicon 优先使用支持 arm64 的镜像，旧 amd64 镜像可能需要模拟运行。
