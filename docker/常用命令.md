# Docker 常用命令与排查

命令中的 `服务名`、`容器名`、`镜像名:标签` 是占位符，执行前替换。Compose 命令应在配置所在目录执行，或使用 `-f /完整路径/compose.yaml` 指定文件。

## 1. 环境和状态

```bash
docker version                    # 客户端与引擎版本
docker compose version            # Compose 版本
docker context show               # 当前 Docker 连接环境
docker ps                         # 运行中容器
docker ps -a                      # 包括停止容器
docker compose ps -a               # 当前 Compose 项目容器
docker compose config --quiet      # 校验，不输出展开后的配置
docker compose config --services   # 查看服务名
docker image ls                   # 本地镜像
docker compose images             # 项目容器使用的镜像
docker stats --no-stream           # CPU、内存等使用情况
docker system df                  # Docker 磁盘占用
```

`docker compose` 使用服务名，`docker exec/logs/inspect` 使用容器名或 ID。容器名可通过 `docker compose ps` 查看，不一定与服务名相同。

## 2. 镜像管理

```bash
docker pull redis:7-alpine                  # 下载镜像
docker image inspect redis:7-alpine         # 镜像详情
docker compose pull redis                  # 拉取项目指定镜像
docker build -t learning-php:8.2 .          # 根据当前目录 Dockerfile 构建
docker compose build 服务名                 # 构建 Compose 中声明 build 的服务
docker login 仓库域名                        # 登录私有仓库
docker tag 本地镜像:标签 仓库域名/项目/镜像:标签
docker push 仓库域名/项目/镜像:标签            # 上传镜像，需要发布权限
```

更新一个现成镜像服务：

```bash
docker compose pull 服务名
docker compose up -d --no-deps 服务名
docker compose logs --tail=100 服务名
```

`pull` 只下载；`restart` 不会换镜像。不同版本需要先修改 Compose 的 `image`。同标签可能被覆盖，更新前记录旧标签/digest并保留旧镜像，便于回退。

## 3. 启动、停止和重建

| 目的 | 命令 |
| --- | --- |
| 创建并后台启动全部服务 | `docker compose up -d` |
| 启动指定服务及其依赖 | `docker compose up -d 服务名` |
| 构建并启动服务 | `docker compose up -d --build 服务名` |
| 强制重建指定服务，不联动依赖 | `docker compose up -d --no-deps --force-recreate 服务名` |
| 停止全部服务，保留容器 | `docker compose stop` |
| 再启动已有容器 | `docker compose start` |
| 重启指定服务 | `docker compose restart 服务名` |
| 移除本项目容器及网络 | `docker compose down` |
| 启动/停止单个已有容器 | `docker start 容器名` / `docker stop 容器名` |

`--no-deps` 适合只更新一个已具备依赖的服务。重建可能改变容器 IP，静态解析上游地址的 Nginx 等服务可能需要重载。不要将 `down -v` 当作普通停止命令，它会删除数据卷。

## 4. 容器日志

```bash
docker compose logs --tail=100                   # 项目最近日志
docker compose logs --timestamps --tail=100 服务名
docker compose logs -f --tail=100 mysql redis      # 持续查看，Ctrl+C 退出
docker compose logs --since=30m 服务名             # 最近 30 分钟
docker logs --timestamps --tail=100 容器名         # 也适用于已退出容器
docker logs -f --tail=100 容器名

# 保存诊断日志
docker compose logs --no-color --timestamps --since=30m > docker-debug.log 2>&1
```

容器日志主要来自标准输出/错误。写入文件的 Laravel、Nginx 或队列日志需要另外查看。分享前检查并移除令牌、密码和用户数据。

## 5. 进入容器、查看文件和进程

```bash
docker compose exec 服务名 sh                     # 进入运行中的服务
docker exec -it 容器名 sh                         # 用容器名进入
docker compose exec -w /app 服务名 sh             # 指定工作目录
docker compose exec 服务名 ls -lah /app
docker compose exec 服务名 tail -n 100 -f /app/storage/logs/laravel.log
docker top 容器名                                # 查看进程
docker cp 容器名:/app/example.log ./example.log   # 复制文件到宿主机
```

`exec` 要求容器正在运行；没有 bash 的精简镜像使用 sh。有些极简镜像也不包含 shell。容器启动即退出时优先查日志，而不是反复 exec。

## 6. 网络、端口及异常退出

```bash
docker port 容器名
docker compose port 服务名 端口号
docker network ls
docker network inspect 网络名
docker inspect 容器名 --format '{{json .NetworkSettings.Networks}}'
docker inspect 容器名 --format '{{json .Mounts}}'
docker inspect 容器名 --format 'status={{.State.Status}} exit={{.State.ExitCode}} oom={{.State.OOMKilled}} restarts={{.RestartCount}} error={{.State.Error}}'

# 宿主机 HTTP 请求示例
curl -v --max-time 10 http://localhost:10102/

# macOS 查看宿主机监听端口
lsof -nP -iTCP:10102 -sTCP:LISTEN
```

不要只凭退出码 137 就判断内存不足，应结合 `OOMKilled`、资源使用和日志。`docker inspect` 的完整输出可能含环境变量中的密码，优先选择要查看的字段。

## 7. MySQL、Redis 验证

下面假设它们是当前 Compose 中的服务：

```bash
docker compose logs --tail=100 mysql
docker compose exec mysql mysql -u app -p app  # 提示后输入密码
```

登录后：

```sql
SELECT 1;
SHOW TABLES;
exit
```

Redis：

```bash
docker compose exec redis redis-cli
```

在客户端输入：

```text
AUTH <实际密码>
PING
QUIT
```

没有启用密码时跳过 AUTH；认证后 PING 应返回 PONG。NOAUTH 表示需要认证，不代表 Redis 没启动。

## 8. 本机 PHP 环境常用命令

以下对应 `/Users/mac/disk2/php-server`，`my-app` 替换为实际业务路径：

```bash
cd /Users/mac/disk2/php-server

# PHP 版本、扩展与配置
docker compose exec php82-fpm php -v
docker compose exec php82-fpm php -m
docker compose exec php82-fpm php --ini
docker compose exec php82-fpm php-fpm -tt

# Nginx：检查实际配置，校验成功才重载
docker compose exec openresty nginx -T
docker compose exec openresty nginx -t &&
docker compose exec openresty nginx -s reload

# 宿主机上的 Nginx 日志文件
ls -lh nginx/log/
tail -n 100 -f nginx/log/ai-healthhub_error.log

# Laravel：检查依赖和清除配置缓存
docker compose exec -w /disk2/www/my-app php82-fpm composer check-platform-reqs
docker compose exec -w /disk2/www/my-app php82-fpm php artisan config:clear
docker compose exec php82-fpm ls -lh /disk2/www/my-app/storage/logs

# 队列与定时任务
docker compose exec php-worker supervisorctl status
docker compose exec php-worker supervisorctl reread
docker compose exec php-worker supervisorctl update
docker compose exec php-worker crontab -u www-data -l
docker compose exec -w /disk2/www/my-app php82-fpm php artisan queue:failed

# 当前独立 MySQL 容器（并非本 Compose 的服务）
docker logs --tail=100 mysql_container
docker exec -it mysql_container mysql -u root -p
```

旧 PHP 项目使用 `php-fpm`。现有 `php-worker` 是 PHP 7.4，不能直接执行要求 PHP 8.2 的队列任务。Laravel 若使用 daily 日志，应选择带日期的实际文件名。

## 9. 数据、清理与备份

```bash
docker volume ls
docker volume inspect 卷名
docker system df
```

删除命令按影响分别选择，先确认对象：

| 命令 | 影响 |
| --- | --- |
| `docker rm 已停止容器名` | 删除容器及其中未持久化的修改 |
| `docker image rm 镜像名:标签` | 删除本地镜像引用；无其他引用时释放镜像 |
| `docker image prune` | 清理未被容器引用的悬空镜像，可能影响旧版本回退 |
| `docker volume rm 卷名` | 删除指定卷中的数据；没有容器使用不代表数据无用 |
| `docker compose down -v` | 删除项目容器、网络及 Compose 管理的卷（外部卷除外） |

MySQL 等数据库优先使用数据库工具做逻辑备份，例如 mysqldump，并验证恢复流程。运行中的数据库目录直接复制可能不一致；命名卷本身也不等于备份。

## 10. 排查顺序

1. 校验 Compose，确认命令所在目录及实际加载文件。
2. 查看 `ps -a`，确认服务未退出、未反复重启。
3. 查看最近容器日志，异常退出再检查退出码与 OOM。
4. 检查端口映射和网络，用实际请求确认问题。
5. HTTP 404 查 root 和挂载；502 查 PHP 上游；500 查业务文件日志。
6. 检查数据库、Redis 的地址、端口、认证，以及应用配置缓存。
7. 修改后执行对应 reload、restart 或 up，再验证原请求。
