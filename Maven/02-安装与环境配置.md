# Maven 安装与环境配置

## 1. 先安装 JDK

本目录使用 JDK 21。Maven 3.9.x 自身最低要求 Java 8，但“能运行 Maven 的 JDK”和“能编译当前项目的 JDK”是两个条件。编译本目录示例需要支持 Java 21 的 JDK。

```bash
java -version
javac -version
```

两个命令都应成功，并指向预期版本。仅有 `java` 命令路径不代表 JDK 可用，macOS 的系统占位命令就是常见情况。

`JAVA_HOME` 指向 JDK 根目录，不是 `bin`，也不是 `java` 可执行文件。

## 2. macOS

### 2.1 使用 Homebrew

已安装 Homebrew 时可以执行：

```bash
brew install openjdk@21
brew info openjdk@21
```

遵循 `brew info` 输出处理 JDK 的系统注册提示。Apple Silicon 和 Intel 的 Homebrew 前缀可能不同，不要直接照抄别人的绝对路径。

在 `~/.zshrc` 中加入：

```bash
export JAVA_HOME="$(brew --prefix openjdk@21)/libexec/openjdk.jdk/Contents/Home"
export PATH="$JAVA_HOME/bin:$PATH"
```

然后重新加载并检查：

```bash
source ~/.zshrc
java -version
javac -version
brew install maven
mvn -v
```

Homebrew 安装的 Maven 版本会随仓库更新，不保证是 3.9.x。团队固定版本时优先使用 Wrapper，或按下一节手动安装。

### 2.2 手动安装 Maven

1. 从 [官方下载页](https://maven.apache.org/download.cgi) 选择需要版本的 **Binary archive**，不是 Source archive。
2. 按官方说明核对 SHA-512 校验值，必要时验证签名。
3. 解压到稳定目录，例如 `~/tools/apache-maven-3.9.x`；这里的 `x` 是占位符，要换成实际目录名。
4. 把该目录下的 `bin` 加入 PATH。

配置示意：

```bash
export MAVEN_HOME="$HOME/tools/apache-maven-3.9.x"
export PATH="$MAVEN_HOME/bin:$PATH"
```

`MAVEN_HOME` 是便于管理路径的变量，不是运行 Maven 必须设置的变量；PATH 正确即可。现代 Maven 通常不需要配置旧资料中的 `M2_HOME`。

## 3. Linux

以提供这些包的 Ubuntu/Debian 版本为例：

```bash
sudo apt update
sudo apt install openjdk-21-jdk maven
java -version
javac -version
mvn -v
```

发行版仓库可能没有 JDK 21，或 Maven 版本较旧。这时使用可信 JDK 发行方和 Maven 官方二进制包，并按实际安装路径设置 `JAVA_HOME`、PATH。不要为了安装工具加入来源不明的脚本或软件源。

手动配置示意，路径必须换成实际值：

```bash
export JAVA_HOME=/path/to/jdk-21
export MAVEN_HOME=/opt/apache-maven-3.9.x
export PATH="$JAVA_HOME/bin:$MAVEN_HOME/bin:$PATH"
```

## 4. Windows

1. 安装 JDK 21。
2. 下载并解压 Maven Binary ZIP，例如解压到 `C:\tools\apache-maven-3.9.x`。
3. 在系统环境变量中设置 `JAVA_HOME` 为 JDK 根目录。
4. 在 PATH 中增加 `%JAVA_HOME%\bin` 和实际 Maven 目录的 `bin`。
5. 重新打开 PowerShell 或 CMD。

```powershell
java -version
javac -version
mvn -v
where.exe java
where.exe mvn
```

有多个安装版本时，PATH 中更靠前的命令通常优先。PowerShell 环境变量的引用写法是 `$env:JAVA_HOME`，不要与 CMD 的 `%JAVA_HOME%` 混用。

## 5. 以 mvn -v 为验收标准

输出应包含：Maven 版本、Maven home、Java 版本和 Java home。

重点看 Maven **实际使用**的 Java home，而不只看 `java -version`。终端、IDE 和 CI 可能分别使用不同 JDK。

## 6. 三类常见配置文件

| 文件 | 作用 |
|---|---|
| Maven 安装目录下 `conf/settings.xml` | 安装级设置 |
| `~/.m2/settings.xml` | 用户级设置，通常放镜像、认证、代理和本地仓库 |
| 项目 `pom.xml` | 项目构建模型，应提交版本控制 |

Windows 的用户目录通常为 `C:\Users\用户名`。用户设置通常覆盖同类全局设置，但具体元素有合并规则，不能理解成整个文件简单覆盖。

最小用户设置示例，不必为了使用 Maven 创建它：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<settings xmlns="http://maven.apache.org/SETTINGS/1.2.0"
          xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
          xsi:schemaLocation="http://maven.apache.org/SETTINGS/1.2.0 https://maven.apache.org/xsd/settings-1.2.0.xsd">
    <interactiveMode>true</interactiveMode>
</settings>
```

常用配置项：

- `<localRepository>`：改变本地仓库位置，写实际路径。
- `<mirrors>`：把指定仓库请求路由到镜像。
- `<servers>`：保存仓库认证；`id` 要匹配实际访问的仓库或镜像 ID。
- `<proxies>`：配置网络代理。
- `<profiles>`：定义可按环境启用的仓库、属性等。

不要把包含密码的个人 `settings.xml` 提交到仓库。认证和镜像例子见 [依赖管理与仓库](04-依赖管理与仓库.md)。

## 7. Maven Wrapper

Wrapper 把项目使用的 Maven 发行版固定下来，让开发机和 CI 使用一致版本。它仍然需要 JDK，首次运行也可能需要网络。

在团队项目根目录用已有 Maven 生成 Wrapper，下面是一个固定版本的示例：

```bash
mvn org.apache.maven.plugins:maven-wrapper-plugin:3.3.2:wrapper -Dmaven=3.9.9
```

生成的文件随 Wrapper 类型而不同，常见包括 `mvnw`、`mvnw.cmd`、`.mvn/wrapper/maven-wrapper.properties`。检查并提交生成的必要文件，保留 Unix 执行权限，核对下载来源与校验配置。

```bash
./mvnw -v
./mvnw clean verify
```

Windows：

```powershell
.\mvnw.cmd clean verify
```

示例工程没有预生成 Wrapper，不能在其中直接假设 `./mvnw` 已存在。先使用 `mvn`，或按上述命令生成。

## 8. 其他配置入口

- `.mvn/maven.config`：项目通用的 Maven 命令行参数；避免放秘密信息。
- `.mvn/jvm.config`：启动 Maven JVM 的参数，例如 `-Xmx1g`。
- `MAVEN_OPTS`：Maven JVM 参数；不等于给测试 JVM 设置参数。
- `mvn -s /path/to/settings.xml ...`：指定用户设置文件。
- `mvn -Dmaven.repo.local=/path/to/repository ...`：临时指定本地仓库。

测试进程的 JVM 参数通常通过 Surefire/Failsafe 的 `argLine` 配置。Maven 的 JVM、编译使用的 JDK、测试运行的 JVM 可以通过工具链等配置分离，排错时要分别确认。
