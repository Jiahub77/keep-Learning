# Maven 概述与核心功能

## 1. Maven 是什么

Apache Maven 是项目构建和管理工具，在 Java 生态中最常见，也可以通过插件处理其他语言和资源。它围绕项目对象模型 POM（Project Object Model）工作。

构建不仅是“编译代码”，通常包括：检查项目、获取依赖、处理资源、编译、运行测试、打包、执行质量检查、发布产物。

没有构建工具时，你可能要手动下载多个 JAR、设置 classpath、调用 `javac`、运行测试、执行 `jar`、复制文件。随着依赖和模块增加，这些操作很难稳定复现。Maven 用项目模型和插件统一这些步骤。

## 2. 核心功能

| 功能 | 解决的问题 | 常见入口 |
|---|---|---|
| 依赖管理 | 根据坐标获取库及其传递依赖，处理版本选择 | `<dependencies>` |
| 标准化目录 | 让工具、IDE、开发者使用一致结构 | `src/main/java` |
| 构建流程管理 | 用统一阶段描述构建顺序 | `mvn verify` |
| 插件扩展 | 编译、测试、打包、质量扫描等具体工作 | `<build><plugins>` |
| 仓库管理 | 下载依赖，安装和发布团队构件 | 本地仓库、私服、Central |
| 多模块构建 | 按模块关系安排构建顺序 | `<modules>`、Reactor |
| 配置复用 | 统一依赖版本、插件和工程规范 | 父 POM、BOM |
| 项目信息与报告 | 描述许可证、开发者，生成文档和报告 | `<licenses>`、`site` |

Maven 不会自动完成所有质量控制。代码检查、覆盖率、集成测试等工作需要对应插件及配置。

## 3. 约定优于配置

Maven 为常见工程提供默认目录和默认行为：

```text
hello-maven/
├── pom.xml
├── src/
│   ├── main/
│   │   ├── java/          # 生产源码
│   │   └── resources/     # 生产资源
│   └── test/
│       ├── java/          # 测试源码
│       └── resources/     # 测试资源
└── target/                # 构建输出，通常不提交
```

遵循约定，就不必为每个项目重新声明源码位置。可以修改目录，但需要有明确原因，并评估插件、IDE 和团队工具的兼容性。

## 4. 一个构建命令背后发生了什么

在有 `pom.xml` 的目录执行：

```bash
mvn clean verify
```

大体过程如下：

1. 启动 Maven，读取命令行参数、全局和用户设置。
2. 读取 POM，解析父 POM、激活的 Profile、属性与继承，形成有效项目模型；过程中可能需要访问仓库。
3. 多模块项目收集参与构建的模块，建立依赖顺序。
4. 根据请求的阶段、packaging 和插件配置计算执行计划。
5. 执行 `clean` 生命周期到 `clean`，通常删除 `target/`。
6. 执行默认生命周期到 `verify`，在需要时解析依赖和插件，由插件处理资源、编译、测试、打包和检查。
7. 输出构建结果；通常遇到错误后停止，某些 Reactor 参数可以改变失败策略。

并不是每个项目都会在每个阶段执行任务。例如没有配置集成测试插件的普通 JAR 项目，执行到 `verify` 也不会自动出现集成测试。

## 5. Maven、JDK、IDE 的关系

```text
开发者 / CI / IDE
        |
        v
      Maven -----> 仓库：获取依赖、插件和项目模型
        |
        v
      插件 -----> 编译器、测试框架、打包工具
```

- JDK 提供编译器和运行时。Maven 进程本身也要在 Java 上运行。
- IDE 可以调用 Maven，但 IDE 自己的编译按钮不一定等同于执行 Maven 生命周期。
- 测试框架提供测试 API 和引擎；Surefire 等插件负责在 Maven 构建中运行测试。
- Spring Boot 是应用框架；其 Maven 插件可以把应用打包为可执行归档。Maven 本身不是 Spring Boot。

## 6. 与前端工具类比

| Maven | 可以帮助理解的前端类比 | 注意 |
|---|---|---|
| `pom.xml` | `package.json` | 模型、继承和生命周期机制不同 |
| Maven 仓库 | npm registry | 坐标及版本解析规则不同 |
| 本地仓库 | 包下载缓存与本地产物仓库 | 默认是用户共享的 `~/.m2/repository` |
| 插件 | 构建和测试工具 | 插件绑定到阶段或由命令直接调用 |
| `target/` | `dist/` 等构建输出 | `clean` 通常会删除它 |

Maven 没有一个与 `package-lock.json` 完全等价、默认适用于所有项目的锁文件。固定版本、统一依赖管理、稳定仓库和构建环境是保证可重复构建的重要条件。

## 7. 什么时候选择 Maven

Maven 适合重视统一结构、成熟插件、团队规范和 Java 生态兼容性的项目。Gradle 的构建模型和脚本表达能力不同；Ant 更接近显式定义执行步骤。选择工具时，优先考虑现有工程、团队熟悉程度和构建需求。

应能回答：Maven 负责编排流程，插件负责执行工作，POM 描述项目，仓库存放构件。
